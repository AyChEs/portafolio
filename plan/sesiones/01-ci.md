## Contexto

Lee `CLAUDE.md` y `plan/REGLAS.md`. Astro 7 estático (`astro.config.mjs`: `trailingSlash: 'always'`, `build.format: 'directory'`), salida en `dist/`. Las 11 páginas son: `/`, `/es/`, `/en/`, `/es/casos/facturacion-saas-recarga/`, `/es/casos/zellige-hotels/`, `/es/casos/cineflow/`, `/en/cases/ev-charging-saas-invoicing/`, `/en/cases/zellige-hotels/`, `/en/cases/cineflow/`, `/es/aviso-legal/`, `/en/legal/` (los slugs salen de `CASES` en `src/content/site.ts`). El modo claro u oscuro sigue a `prefers-color-scheme`. No hay hoy ni script de auditoría, ni `astro check`, ni CI (`.github/` no existe).

## Tareas

1. Dependencias de desarrollo: `npm i -D @astrojs/check typescript @playwright/test @lhci/cli`. Scripts en `package.json`:
   ```json
   "check": "astro check",
   "audit": "node scripts/auditoria.mjs",
   "lhci": "lhci autorun"
   ```
2. `npx astro check`: arregla los errores de tipos que salgan **sin cambiar comportamiento ni aspecto**. Si alguno exige cambiar algo visible, déjalo y anótalo en el PR.
3. `scripts/auditoria.mjs` (Playwright, Chromium): arranca `npx astro preview --port 4321` (o usa `BASE_URL` si se pasa), y para cada una de las 11 páginas × anchos 390 y 1440 (alto 844 y 900) × `colorScheme` `light` y `dark` (`browser.newContext({ viewport, colorScheme, reducedMotion: 'reduce' })`):
   - recoge errores de consola (`page.on('console')` tipo `error`) y `pageerror`;
   - comprueba desplazamiento horizontal (`document.documentElement.scrollWidth > innerWidth`);
   - comprueba imágenes rotas (`img` con `complete && naturalWidth === 0`, tras desplazar hasta el final para cargar las perezosas);
   - ignora solo el error esperado de Turnstile/Analytics si no hay claves (lista blanca explícita y comentada; nada más);
   - imprime una tabla y sale con código 1 si hay cualquier fallo. Guarda capturas en `plan/capturas/auditoria/` solo con `--capturas`.
   44 combinaciones en total.
4. `lighthouserc.json` en la raíz:
   ```json
   {
     "ci": {
       "collect": {
         "staticDistDir": "./dist",
         "url": ["http://localhost/es/", "http://localhost/es/casos/zellige-hotels/", "http://localhost/es/aviso-legal/"],
         "numberOfRuns": 1,
         "settings": { "preset": "desktop" }
       },
       "assert": {
         "assertions": {
           "categories:performance": ["error", { "minScore": 0.95 }],
           "categories:accessibility": ["error", { "minScore": 0.95 }],
           "categories:best-practices": ["error", { "minScore": 0.95 }],
           "categories:seo": ["error", { "minScore": 0.95 }]
         }
       },
       "upload": { "target": "filesystem", "outputDir": ".lighthouseci" }
     }
   }
   ```
   y un segundo `lighthouserc.mobile.json` igual sin `preset` (móvil por defecto). Script `"lhci:mobile": "lhci autorun --config=lighthouserc.mobile.json"`. Añade `.lighthouseci/` a `.gitignore`. Comprueba que `staticDistDir` resuelve bien las rutas con barra final; si no, usa `startServerCommand: "npx astro preview --port 4321"` y URLs `http://localhost:4321/…`.
5. `.github/workflows/ci.yml`:
   ```yaml
   name: CI
   on:
     push:
       branches: [main, claude/zealous-franklin-er41ad, plan/cierre]
     pull_request:
   jobs:
     build:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         - uses: actions/setup-node@v4
           with: { node-version: '22', cache: npm }
         - run: npm ci
         - run: npm run check
         - run: npm run build
         - run: npx playwright install --with-deps chromium
         - run: npm run audit
         - run: npm run lhci
         - run: npm run lhci:mobile
   ```
   (Cuando exista `npm test`, la sesión 02 añade el paso.)
6. Ejecuta todo en local y después en el CI del PR. Si Lighthouse da menos de 100 en algo, explica en el PR qué y por qué (sin bajar el umbral de 95).
7. README, sección «Calidad medida»: cambia «probadas con simulaciones» y la frase de Lighthouse para decir que lo comprueba el CI en cada PR, con los comandos.

## No hacer

- No cambies el aspecto, los textos ni la estructura de la web.
- No bajes ningún umbral para que pase.
- No configures despliegues ni toques Cloudflare.

## Criterios de aceptación

- `npm run check`, `npm run build`, `npm run audit` y `npm run lhci` y `lhci:mobile` en verde en local y en el CI del PR.
- `npm run audit` falla si se introduce un desbordamiento (pruébalo una vez añadiendo `width:2000px` a un elemento y deshazlo; cuéntalo en el PR).
